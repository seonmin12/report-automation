# Validation Rules

각 규칙이 어느 모듈에 구현되어 있는지 함께 표기했습니다. 코드가 최종 근거이므로, 문서와
동작이 어긋난다면 코드가 맞습니다 — 이 문서를 갱신해 주세요.

## 1. 포털-RAW 실적 대사 (`src/compare.py`)

- 비교 단위는 **사업자코드 + 상품코드** 조합입니다.
- 포털 실적(신규건수/해지건수/순증건수)과, RAW를 당월 기준으로 직접 집계한 값(`src/aggregate.py`)을
  outer merge로 비교합니다.
- 핵심 비교 지표는 **순증건수**입니다. 차이(`차이` = 포털값 − RAW값)와 차이율(`차이율(%)`)을 계산합니다.
- 사업자/상품 조합이 포털 또는 RAW 어느 한쪽에만 존재하면 `존재출처`를 `포털에만 존재` /
  `RAW에만 존재`로 표시하고 무조건 `확인필요`로 분류합니다.
- 양쪽에 다 존재해도 차이율이 임계치(`DIFF_THRESHOLD_PCT = 1.0%`)를 초과하면 `확인필요`로 분류합니다.
- 그 외에는 `정상`입니다.

## 2. 요금제/상품 매핑 검증 (`src/validate.py`)

4가지 이슈를 독립적으로 검사한 뒤 하나의 오류 목록으로 통합합니다.

| 이슈 유형 | 판단 기준 |
|---|---|
| 매핑누락 | RAW에 등장하는 상품코드가 매핑 기준표에 존재하지 않음 |
| 중복 | 매핑 기준표에 동일 상품코드가 2행 이상 등록됨 (`duplicated(keep=False)`) |
| 비활성사용 | 매핑 기준표상 `사용여부 = 비활성`인 상품코드로 RAW 거래가 발생함 |
| 명칭불일치 | 동일 상품코드에 대해 매핑표/RAW/포털의 상품명 중 하나라도 다름 |

- 매핑누락·비활성사용은 상품코드 단위로 집계되어 거래건수와 함께 표시됩니다.
- 명칭불일치는 매핑표/RAW/포털 3곳의 상품명을 나란히 비교해서 보여줍니다.

## 3. 검증상태 판정 (`src/aggregate.attach_validation_status`)

- 사업자 단위 요약(`사업자별누적가입자`)에 `검증상태` 컬럼을 추가합니다.
- 아래 중 하나라도 해당하는 사업자는 `확인필요`, 그 외에는 `정상`입니다.
  - 실적비교에서 `이상여부 = True`인 사업자/상품 조합을 하나라도 보유
  - 매핑 검증 4종 이슈(매핑누락/중복/비활성사용/명칭불일치) 중 하나라도 걸린 사업자

## 4. 산출물 반영 원칙

검증 결과(정상/확인필요, 오류유형별 건수)는 아래 모든 산출물에 **동일한 계산 결과**로 반영됩니다.
Excel 리포트, 텍스트 요약, PNG 요약 이미지, 이메일 초안, 웹 대시보드가 각자 따로 계산하지 않고
같은 `src/` 파이프라인 함수를 재사용합니다.

- Excel 리포트: `요약` / `실적비교` / `요금제미매핑이슈` / `오류상세` / `사업자별누적가입자` 5개 시트
- 텍스트 요약 / PNG 이미지: 사업자별 `검증상태`를 문구·색상으로 강조
- 웹 대시보드: 동일한 요약 카드 + 오류상세 테이블을 HTML/JSON으로 제공
